# 情境啟動

在手機上建立規則：位置、Wi-Fi、開始充電、藍牙連線可以單獨使用，也可以用「而且」與「或」組合。條件成立時，自動開啟你指定的 App。介面預設繁體中文，系統語言是英文時改顯示英文。

這是給自己側載用的工具，不是上架 Google Play 的版本。`minSdk 26`、`targetSdk 35`。

## 需要的權限，以及為什麼

| 權限 | 原因 |
| --- | --- |
| 精確位置，並且選「一律允許」 | 地理圍欄在 App 關掉後仍要知道你是否進入或離開範圍。只選「僅在使用時」，背景服務在 Android 14 以後會被拒絕。 |
| 定位服務總開關 | 關掉的話，Wi-Fi 名稱與地理圍欄都不會有結果。 |
| 附近的 Wi-Fi 裝置（Android 13+） | 讀取附近網路。這個 App 不用 Wi-Fi 來推算地圖座標。 |
| 通知（Android 13+） | 常駐的監控通知，以及無法直接開啟目標 App 時的點一下通知。前景服務通知本身有時仍會顯示。 |
| 顯示在其他應用程式上層 | Android 10 起，背景程式通常不能打開另一個 App。使用者允許這個權限後，系統才放行背景啟動。 |
| 忽略電池最佳化 | 降低待機時被凍結的機會。 |
| 精確鬧鐘 | 時間窗開始的那一分鐘準時再檢查一次。沒有的話，前景服務仍會定期檢查，但待機時可能晚幾分鐘。 |
| 全螢幕通知（Android 14+） | 直接開啟失敗時的備援。 |
| 藍牙連線（Android 12+） | 讀取已配對裝置，以及車機這類裝置是否已連上。 |
| 開機完成 | 重新開機後把監控服務叫回來。 |

充電狀態不需要額外權限。畫面會顯示系統回報的電壓、電流與估計功率，**只供對照**。電流正負號各廠牌不同，功率用絕對值估算。Android 讀不到充電器廠牌或標稱瓦數，所以「家裡的充電器」和「公司的充電器」無法直接區分，請改用 Wi-Fi、位置或藍牙一起判斷。

### 各廠牌還會再殺一次背景

小米／紅米請開自啟動，省電策略選無限制。三星請把電池設成不受限制，並從休眠應用程式移除。OPPO、realme、vivo 要允許自啟動與背景活動。華為請改手動管理，打開自啟動。若你在系統裡強制停止這個 App，下次重開機也不會自動恢復，要再手動打開一次。

## 建立規則

1. 在「規則」按新增。
2. 加一或多個**必要條件**。每一塊都要成立。同一塊裡若有多個條件，只要其中一個成立即可。
   - 位置：在地圖上點選，或用目前位置，或手動輸入經緯度。可選「進入」或「離開」。
   - Wi-Fi：預設看**掃描結果**，手機不必連上那個網路。名稱可比對「包含」（預設，例如 `7-11` 對到 `7-11_FREE`）、「完全相符」、「開頭是」或正規表達式，並可選忽略大小寫。掃描裡任何一個相符的網路都算，訊號與停留看其中最強的那個。已連線只是選用。可再限制 BSSID。
   - 開始充電：可複選 USB、AC、無線；都不選代表任何電源。以「電源接上」為準，包含已經充滿但仍插著。
   - 藍牙：從已配對裝置挑選，例如車機。
3. 例子：
   - 開始充電 **而且** 已連上家裡的 SSID。
   - 開始充電 **而且**（在公司範圍內 **或** 掃到公司 Wi-Fi）。
   - 開始充電 **而且** 車機藍牙已連線。
4. 選擇要開啟的 App。
5. 冷卻時間預設 **30 分鐘**。啟動過一次之後，這段時間內即使離開再遇到下一家（例如連續經過好幾家 7-ELEVEN）也不會再開。設成 0 就只靠條件解除來重新待命。
6. 可加上星期與一個以上的時段。時間用手機的本地時區。

### 時間窗

- 不開啟時，全天有效。
- 開始時刻包含，結束時刻不包含。`09:00–18:00` 在 09:00:00 會算進去，18:00:00 不算。
- 結束時間早於開始時間代表跨日，而且這一段從**有勾選的那天**開始，延續到隔天。例如只勾週五、`22:00–02:00`，會包含週六凌晨 02:00 之前，不包含週六晚上。週一到週五的 `22:00–02:00` **不**包含週一凌晨，因為那是週日的延續。
- 開始與結束設成同一時間，代表勾選的那天全天。
- 多個時段是「或」：落在任一段即可。
- **時間窗開始時若條件已經成立**（人已經在範圍內、Wi-Fi 已停留夠久、已經在充電、藍牙已連著），會在時間窗開始時啟動**一次**。
- 離開型的位置條件不會因為時間窗開始就啟動，只在時間窗內真正離開時啟動。
- 同一個有效狀態不會重複啟動。時間窗結束、離開範圍、Wi-Fi 降到重新武裝門檻或消失夠久、拔除電源、藍牙斷線，都會重新待命。下一個時間窗若人還在，會再啟動一次。
- 啟用規則時若條件與時間窗都已經成立，下一次檢查會啟動一次。

### 避免路過就觸發

**Wi-Fi（掃描，不必連線）**

- 預設模式是「掃描到」。只要附近掃到相符的 SSID 就成立，例如名稱**包含** `7-11` 就打開 7-ELEVEN，手機不會連上那組 Wi-Fi。
- 比對套用在掃描結果裡的**每一個**網路。RSSI 門檻與停留時間看其中**訊號最強**的那個。
- 最低訊號預設 **-65 dBm**。必須大於或等於門檻。編輯畫面會顯示目前最強的相符訊號。
- 停留時間預設 **60 秒**。已連線模式（選用）也要等這段時間。設成 0 則立刻成立。
- 重新武裝：最強相符訊號低於 `門檻 - 10 dBm`，或相符網路連續消失 **3 分鐘**。
- 另外每條規則有冷卻時間，預設 30 分鐘，避免一路經過很多家時重複開啟。
- 兩次有效掃描如果間隔超過 5 分鐘，尚未完成的停留會重算。
- 掃描不需要已連上任何 Wi-Fi。Wi-Fi 要開著，定位服務也要開著。部分手機在系統設定的「Wi-Fi 掃描」（即使 Wi-Fi 關閉仍掃描）打開時，Wi-Fi 關掉也掃得到。Android 仍會限制掃描頻率。

**位置**

- 半徑可小到 30 公尺（預設 100 公尺）。小於 100 公尺時，畫面會提醒：手機 GPS 誤差常常就有 30–100 公尺。
- 停留時間預設 60 秒。有 Google Play 服務時，用地理圍欄的 loitering delay，等 `GEOFENCE_TRANSITION_DWELL` 才算進入。沒有 Play 服務時，由前景服務的定位點自己計時。
- **精度比半徑還差的定位點會直接忽略**，不拿來判定進入，也不拿來把你趕出範圍。
- 一旦判定在範圍內，要再走出「半徑 + 30 公尺」才算離開，避免站在圓邊時來回觸發。
- 只是路過、停留時間不夠，進入與離開都不會啟動。

## 背景怎麼運作

- 有啟用中的規則，而且已允許背景位置時，會啟動前景服務，通知欄保持一則「監控中」。
- 位置優先用 Play 服務地理圍欄（進入、停留、離開）。沒有 Play 服務時，改向系統要 GPS／網路定位。
- Wi-Fi 用 `ConnectivityManager` 聽目前連線，並動態註冊掃描結果。需要補滿停留時間時，大約每 30 秒嘗試掃一次；否則較少掃。已連線的規則靠連線回呼與約 15 秒的檢查推進停留時間，不依賴掃描頻率。
- 充電聽 `ACTION_BATTERY_CHANGED`。藍牙聽 ACL 連線／斷線，並在服務啟動時查詢已連上的耳機與 A2DP 裝置。
- 時間窗的下一個邊界會設鬧鐘；服務自己也會定期再看一次。
- 開機與更新 App 之後會試著把服務叫回來。
- 條件成立時，若已允許「顯示在其他應用程式上層」，就直接 `startActivity`。失敗或尚未允許時，改發一則高優先通知（可能帶全螢幕意圖），點一下才開啟。

## 限制

- **Wi-Fi 掃描有節流，而且通常要開定位。** 前景 App 在 Android 9 以後大約每 2 分鐘最多 4 次；這個 App 約每 30 秒請求一次，被拒絕就沿用上一筆結果，但不會把過期掃描拿來提前完成停留。實際等待可能比 60 秒更久。開發者選項可以暫時關掉 Wi-Fi scan throttling。沒連上任何網路也可以掃。若 Wi-Fi 關閉，要看系統是否允許「Wi-Fi 掃描」（設定裡常寫成即使不用 Wi-Fi 也掃描）。
- **背景開啟其他 App 仍可能失敗。** `SYSTEM_ALERT_WINDOW` 目前仍是系統允許的例外，但新版 Android 可能再收緊。失敗時請點通知。
- **前景服務類型。** 服務宣告 `location`，有藍牙權限時在 Android 14 以上再加上 `connectedDevice`。沒有「一律允許」位置時，服務不會留在背景。
- **地理圍欄**最多約 100 個，初始觸發與停留由 Play 服務決定，可能比設定的秒數再晚幾秒到幾十秒。
- **OEM 省電**仍可能在划掉背景或幾小時後殺掉服務。強制停止後不會在開機時復原。
- 目標 App 若被停用、沒有啟動畫面，或你沒裝，紀錄會寫啟動失敗。
- 偵錯 APK 用偵錯金鑰簽名。之後若改用正式金鑰，需要先移除再安裝。

## 開發

需要 JDK 21 與 Android SDK 35。

```bash
./gradlew :core:test :app:assembleDebug
```

規則比對、停留、訊號門檻、遲滯、時間窗與組合條件的測試在 `core`，不依賴 Android 框架。產物在 `app/build/outputs/apk/debug/app-debug.apk`。
